2. 推薦操作流程

A. 一般正式查看

  1. 直接執行 P1008_APP.bat。
  2. Launcher 讀取 review package；若無待決，會進入新 UI。
  3. 新 UI 讀取正式 CSV 作為主要 KPI 與圖表基準；若有 runtime snapshot，必須回 Launcher 確認是否只是臨時觀察。

B. 盤中或臨時觀察

  1. 在 Launcher 按「一鍵更新資料與資訊」或「只更新資料」。
  2. 在 Launcher 確認 DRY_RUN.md / review package 是否標示缺欄、沿用值、資料來源。
  3. Launcher gate 通過後才進新 UI；若有缺欄或 Owner 待決，停留在 Launcher 審查。

此模式只能提示風險與重審，不得產生正式決策結論。

C. 收盤後正式發布

  1. 收盤後在 Launcher 執行一鍵資料流程，產生候選檔與 review package。
  2. 查看 Launcher 的 readiness、候選檔、缺欄、總經/新聞/FX 待決。
  3. 若候選日期為週末或交易所休市日，Launcher / 新 UI 應沿用最近正式交易日收盤價供 PB 與畫面連續；該列需標示 MARKET_CLOSED_CARRY_FORWARD，不得當成新交易日收盤價 append。
  4. readiness 達 95% 且無核心缺欄時，Owner 才可在 Owner Formal Publish Gate 輸入強確認字串。
  5. 發布完成後由 Launcher 檢查正式 CSV hash / manifest，通過後再進新 UI 檢查正式基準。
  6. P1008_3_OWNER_PUBLISH_CSV.bat 僅作備援。

旁路 CSV：總經事件 / FX 趨勢觀察

  • macro_snapshot.csv 維持既有 18 欄，不擴欄、不塞新聞判斷。
  • data/macro_event_observations.csv 承接 Owner 輸入或 v2 核准公開來源掃描到的新聞、黑天鵝、地緣政治、Fed/CPI/油價事件；無來源證據時不得自動幻想新聞。
  • data/fx_trend_observations.csv 承接 TWD/USD、DXY、JPY/USD、Fed/BOJ 利差與 FX 壓力觀察；缺 JPY 或 BOJ 時標示資料缺口。
  • 兩個旁路 CSV 的 Actionable 必須永遠是 false；UI 只能顯示重審提示，不得改 HOLD、不得啟用規則。

固定新聞掃描與事件時間差保護

新聞掃描應由 Windows Task Scheduler 固定呼叫 BAT；BAT 只產生 staging event candidate 與 dry-run 註記，不直接 append 正式 CSV。手動 BAT 僅作補跑或 Owner 指定事件輸入。

3. 正式 CSV 與 runtime snapshot 的判讀規則

正式 CSV

  • 是戰情室 KPI、估值圖、正式報告的基準。
  • 只能由 Launcher Owner gate 或備援 Owner 發布流程 append，不允許一鍵更新或抓取器直接覆寫。
  • 每次發布都要更新 SHA-256、rowCount、dateRange 或 lastPublishedAt。
  • 可用於正式判讀，但仍維持 actionable:false。

runtime snapshot

  • 是臨時快照，用來滿足盤中與收盤後快速觀察。
  • 可以讓戰情室暫時更新數字、圖表、風險提醒。
  • 必須顯示中文資料狀態，例如「臨時即時快照，尚未核准發布」。
  • 不能提升為正式資料，除非經過 staging 檢核與 Owner 發布。

5. 決策者看戰情室時要先確認什麼

  1. 頂部資料狀態是否為正式資料、臨時快照、資料過期或待核准。
  2. KPI 是否有 N/A、沿用值、觀察欄位或資料註記扣分。
  3. 市場情報是否只影響風險提醒與重審提示，不啟用交易規則。
  4. 正式報告輸出前，需以正式 CSV 為主；runtime snapshot 只能作為附註與盤中觀察。
  5. 若資料狀態不是正式發布，報告需明確標示「僅供觀察，尚未核准發布」。
MIDR / MRD 僅供估值風險輔助觀察，不是主結論、不做主模組、不產生買賣訊號。主畫面只顯示「估值偏離觀察」與中文結論；MRD、MIDR、公式拆解與門檻值應放在 UI 展開區。

6. 週/月戰報輸出規則

戰報不是市場評論，也不是把主程式畫面截圖整理成報告。每次戰報的主要目標，是檢查目前持股風險是否仍可承受，以及戰情室原本的決策邏輯是否需要修正。

戰報必答五問

  1. 目前持股風險是否比上一期升高？
  2. 現行 HOLD / 觀察邏輯是否仍被數據支持？
  3. 哪些 KPI 或總經條件正在挑戰原本判斷？
  4. 若發生黑天鵝或財報惡化，現有規則是否能及時重審？
  5. 戰情室邏輯是否需要修正，還是只需維持觀察？

三層主結論

  • 持股風險狀態：可承受、升高需觀察、需重審。
  • 決策邏輯狀態：有效、需監控、需修正、資料不足。
  • Owner 動作：不變更、補資料、重審門檻、修正規則。
輸出狀態使用條件Owner 動作
LOGIC_VALID正式資料鏈完整，主要 KPI 與原結論一致。維持原邏輯，列支持證據。
WATCH_REQUIRED風險升高但尚未推翻主論點。提高觀察頻率，追蹤接近門檻 KPI。
REVIEW_REQUIRED關鍵風險或資料註記足以要求人工判斷。Owner 重審，不自動修改規則。
REVISION_REQUIRED回測、財報或黑天鵝檢討證明原規則不足。提出修正案，需 Owner 核准後才可改權重、門檻或資料源。
DATA_BLOCKED正式 CSV、schema、hash 或核心欄位不足。只能產生觀察版，先補資料或重新發布。
正式戰報必須以正式 CSV 與 manifest/hash 為基準。runtime snapshot 或 staging candidate 可以出現在附註與觀察版，但不能直接改正式結論。

MIDR / MRD 在戰報中的位置

  • 戰報主文不以 MIDR / MRD 當標題，也不把數值當主結論。
  • 主文只寫決策語言：例如「估值偏離觀察：未出現明顯超跌，統計分數偏謹慎」。
  • 詳細數值、公式、權重、門檻與來源層級放在附錄或稽核明細。
  • 若數值來自正式 CSV 衍生計算，需標示「正式欄位衍生」；若含觀察欄位，需中文註記。
  • 所有 MIDR / MRD 輸出維持 actionable:false，只影響估值風險提醒與重審頻率。
研報庫已新增 P1008_DECISION_AUDIT_REPORT_STANDARD_20260701.md，作為週/月戰報的格式標準與驗收依據。

7. 流程結論

P1008_1_UPDATE_DATA.bat、P1008_3_OWNER_PUBLISH_CSV.bat 與 Launcher 沒有功能重複。Launcher 是決策者中控；BAT 是備援與維運入口。平常開戰情室先進 Launcher；需要臨時觀察或日常更新按一鍵資料流程；要升格正式資料則使用 Launcher 的 Owner Formal Publish Gate。

這個分層能同時滿足兩件事：決策者臨時需要最新資訊時，戰情室可以即時反映；正式報告和正式 KPI 判斷，又不會被未核准資料污染。

週/月戰報則負責更高一層的檢查：持股風險是否升高、原本 HOLD / 觀察邏輯是否仍有效、戰情室規則是否需要 Owner 核准後修正。

8. 固定新聞掃描器 v2 實作流程

P1008_4_NEWS_SCAN.bat 是觀察型新聞掃描入口，底層呼叫 tools/warroom_news_scanner_v2.py。它可依 data/NEWS_SCAN_SOURCE_MANIFEST.json 抓取 enabled 且 connectorStatus=APPROVED 的公開來源，並只產生 staging/YYYY-MM-DD/NEWS_SCAN.json、NEWS_SCAN.md、必要時的 macro_event_observations_candidate.csv，以及 runtime/warroom_news_scan_snapshot.json；正式 CSV、主結論 IC 與 KEEP_DISABLED 規則都不會被修改。

項目規則Owner 動作
無事件掃描只留下 no-event scan report 與 runtime snapshot；不把空候選列加入待發布清單。不需發布，首頁顯示 no-event。
OBSERVE / WATCH進入 staging candidate，但 Actionable=false；單一媒體最高只能 WATCH，未驗證來源最高只能 OBSERVE。檢查來源、摘要與是否需要寫入旁路 CSV。

crawler healthv2 會在 runtime snapshot 記錄 networkSummary、sourceHealth、optional dependency 狀態，以及每個來源的成功/失敗/錯誤類型。若多數來源為 CONNECTION_REFUSED、timeout、DNS 或 proxy 錯誤，先處理網路/proxy，再判斷是否補跑。

若本機 Python HTTPS 被防火牆或 proxy 擋住，Launcher 會顯示逐來源錯誤；v2 也可在 Playwright 可用時嘗試 Edge/Chrome browser-mode fallback。系統不得繞過公司網路政策，僅能使用合法 proxy、系統瀏覽器 session 或 Owner 核准來源。

9. 定期戰報產生器與單一窗口閉環

P1008_5_GENERATE_REPORTS.bat 是本機日報、週報、月報的產生入口。它只讀取正式 CSV、旁路 CSV、runtime/warroom_news_scan_snapshot.json 與 runtime/warroom_event_review_state.json；輸出只限於 reports/generated/、reports/P1008_REPORT_MANIFEST.json、runtime/warroom_report_manifest.json 與 log。

產物用途邊界
reports/P1008_REPORT_MANIFEST.json提供首頁、reports.html 與 report_viewer.html 讀取最新戰報索引。只是索引 manifest，不是正式資料。
runtime/warroom_event_review_state.json追蹤 WATCH / REVIEW_REQUIRED 事件是否仍等待 Owner ack。屬於 runtime 治理狀態，不會 append 旁路 CSV。
Launcher / 新 UI 分工Launcher 是更新與 Owner gate 入口；新 UI 是決策摘要；主 IC、事件/FX 與資料治理卡片才進入舊 UI 明細錨點。6 大系統卡片留在新 UI 摘要，不各自打開舊 UI 視窗。
最新戰報卡依 manifest 顯示最新日報、週報、月報狀態。戰報維持 actionable:false。
當 Owner 需要刷新本機靜態戰報時，於資料更新、新聞掃描與 review-only 檢查後執行 P1008_5_GENERATE_REPORTS.bat --date YYYY-MM-DD --period daily|weekly|monthly。此命令永遠不修改正式 CSV。
若 Launcher 或新 UI 曾顯示 HOLD_UNDER_REVIEW，下一份戰報必須回答：事件是否解除、是否已反映在 KPI / FX / 市場資料、原 HOLD 邏輯是否仍有效。

10. BAT 使用方式：手動、排程與戰報產出

本套件的 BAT 分成「手動執行」與「註冊後由 Windows 排程自動執行」兩種。預設情況下，沒有任何 BAT 會自動發布正式 CSV，也不會自動改主結論 IC。

BAT預設是否自動何時使用會產生什麼不會做什麼
P1008_4_NEWS_SCAN.bat 手動；只有完成排程註冊後才會由 Windows 自動執行。 開盤前、盤中、收盤後、夜間國際事件檢查，或 Owner 懷疑有重大事件時補跑。 staging/YYYY-MM-DD/NEWS_SCAN.json、NEWS_SCAN.md、runtime/warroom_news_scan_snapshot.json，必要時產生事件 candidate。 不抓未核准來源、不發布正式 CSV、不改 HOLD、不啟用 KEEP_DISABLED。
P1008_4_REGISTER_NEWS_SCHEDULE.bat 手動一次性設定工具；雙擊預設只預覽，不改 Windows。 Owner 決定要讓新聞掃描固定自動跑時使用。加 --register 才建立 08:10、12:30、15:30、21:30 四個排程；加 --remove 可移除。 Windows Task Scheduler 工作項目，工作內容是呼叫 P1008_4_NEWS_SCAN.bat --dry-run --allow-network --scan-window ...；實際可抓來源仍受 manifest 的 enabled / APPROVED 控制。 不掃新聞、不產生報告、不發布 CSV；它只管理排程。
P1008_5_GENERATE_REPORTS.bat 手動；目前不建議自動排程，避免未完成 Owner review 就生成正式觀感的戰報。 資料更新、新聞掃描、Owner publish review-only 完成後，需要日報、週報或月報時執行。 reports/generated/ 戰報、reports/P1008_REPORT_MANIFEST.json、runtime/warroom_report_manifest.json、reports/generated/latest_report.html。 不更新資料、不抓新聞、不 append 正式 CSV、不改 HOLD。
P1008_4_NEWS_SCAN.bat v2 的固定排程可以抓取已核准公開來源，但仍不是正式資料發布工具。若來源失敗，Launcher 應顯示 connector health；若掃到單一媒體事件，最高只到 WATCH；只有官方來源或多來源交叉驗證且同時具備鴻海直接事件、CSP capex / AI data center 需求、GB200/GB300/AI server、供應鏈中斷、關稅/制裁等明確觸發詞，才可進 REVIEW_REQUIRED。

建議日常順序

  1. 需要最新資料時，先執行 P1008_1_UPDATE_DATA.bat 產生 staging/runtime 候選。
  2. 需要事件保護時，執行 P1008_4_NEWS_SCAN.bat --dry-run --allow-network；若已註冊 Windows 排程，則平時可由排程自動補跑。
  3. 正式資料發布前，優先在 launcher.html 的 Owner Formal Publish Gate 做 review；Owner 輸入強確認字串後才會 append。P1008_3_OWNER_PUBLISH_CSV.bat 保留為備援。
  4. 需要戰報時，執行 P1008_5_GENERATE_REPORTS.bat --date YYYY-MM-DD --period daily；週報或月報則把 daily 改成 weekly 或 monthly。
  5. 決策者閱讀時，優先用 P1008_APP.bat 開啟 launcher.html；Launcher gate 通過後再進入新 UI、研報庫、SOP 或最新戰報。
資料夾雙擊 reports.html 屬於 file:// 模式，部分瀏覽器會阻擋 manifest 或 markdown 讀取。若只是要看最新產生戰報，可點研報庫中的「最新本機定期戰報」或直接開 reports/generated/latest_report.html；若要完整互動閱讀，請使用 P1008_2_OPEN_WARROOM.bat。

12. Launcher 控制台與 Owner Gate

決策者應從 Windows 檔案總管直接雙擊 P1008_APP.bat 啟動；它會呼叫 P1008_2_OPEN_WARROOM.bat 啟動本機 App server，預設開啟 launcher.html。Launcher 負責資料更新、總經 / 新聞 / FX 審查、Owner formal publish gate，以及是否可進入新 UI 的判斷。若 Launcher 顯示 Codex 沙盒，代表該 server 可能繼承 Codex 網路限制，不能當作正式 connector 驗收結果。

P1008_APP.bat 會優先以 Edge / Chrome App 視窗與 fs=1 參數開啟 Launcher，使 Launcher、新 UI、研報庫、單篇戰報與 SOP 在互相跳轉時維持戰情室沉浸模式。瀏覽器原生 Fullscreen API 會在跨頁導覽時被瀏覽器取消，因此系統以 App 視窗 + p1008_immersive_mode 保存畫面狀態；若畫面不是沉浸模式，請關閉舊 localhost 視窗後重新雙擊 P1008_APP.bat。

API / 動作用途安全邊界
GET /api/p1008/review-package讀取候選 CSV、readiness、總經/新聞/FX 待決、Owner 強確認字串。只讀審查包。
POST /api/p1008/run/default依序執行 preflight、update data、news scan、daily report、refresh。不呼叫 Owner publish，不修改 HOLD。
POST /api/p1008/run/update-data只補跑 staging/runtime 資料更新。正式 CSV 不應改變；若 hash 改變，App 標示錯誤。
POST /api/p1008/run/news-scan只補跑 v2 觀察型新聞掃描，並回寫 networkSummary / sourceHealth 給 Launcher。只有來源 manifest 中 enabled=true 且 connectorStatus=APPROVED 的網路來源可連網；其餘來源一律跳過。
POST /api/p1008/run/report只產生日報與最新本機戰報 HTML。只讀正式 CSV 與 runtime / sidecar，不 append CSV。
POST /api/p1008/publish/formalOwner 在 Launcher 輸入 OWNER_APPROVE_PUBLISH_YYYY-MM-DD 後 append 正式 CSV。只能呼叫既有 owner_publish_csv_v2.py gate；一鍵資料流程不得觸發。
GET /api/p1008/status回傳目前 job、步驟、Owner review 狀態、來源 manifest 與正式 CSV hash 檢查。只讀狀態。
Launcher gate 通過後才進入新 UI。若存在 CSV candidate、總經/FX 缺欄、新聞 WATCH / REVIEW_REQUIRED、Owner ack 未完成或 readiness blocked，決策者應停留在 Launcher 審查。
一鍵資料流程不是正式資料發布工具。正式 CSV append 只能由 Launcher 的 Owner Formal Publish Gate 或備援 P1008_3_OWNER_PUBLISH_CSV.bat 完成。

14. 新聞來源 URL 維護與 crawler 成功率判讀

URL 維護規則

  • 新聞 crawler 不得只依賴站內搜尋 URL；每個重要來源需保留首頁、分類頁、RSS/Atom 或 sitemap 作主路徑。
  • NEWS_SCAN_SOURCE_MANIFEST.json 的 deprecatedUrlPatterns 會列出已知失效 URL；warroom_news_scanner_v2.py 會在 URL build 階段略過這些路徑。
  • 鉅亨網目前以 https://news.cnyes.com/news/cat/tw_stock 等分類頁為主，https://news.cnyes.com/search?q=... 為輔；不得再使用舊的 search/all?keyword=...。
  • 鴻海官方來源以中文站 /zh-tw/press-center/press-releases/latest-news 與 IR 月營收報告頁為主，不再使用舊的 English press release 空白頁。
  • 工商時報以首頁、即時、證券、產業、國際等分類頁為主；search URL 只作輔助，不可成為唯一路徑。
Launcher 的 crawler 成功率只計算 requiresNetwork=true 的網路來源；Owner manual event input 是本地 Owner 輸入，不列入 0/16 或 13/16 分母。若網路來源顯示 0%，代表本次 App server 的 connector/source 未取得資料，應檢查 proxy/firewall、來源 manifest、browser-mode fallback 依賴；只有剛更新 server 程式碼或懷疑舊 server 卡住時，才使用 --fresh。
