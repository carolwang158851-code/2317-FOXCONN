## 二、ORANGE 緊急審查 SOP

### 2.1 回應時間要求

```
Owner 回應期限：
  • 標準期限：7個自然日（2026-07-03 前）
  • 理由：退休族Owner不需要即時回應，
    7天足以在不影響日常生活的情況下完成審查
  • 不設「小時級」期限：
    ORANGE等級不是緊急危機，是「需要關注的問題」
    強制Owner在24小時內回應會製造不必要的壓力

超時定義：
  • 超過7個自然日未回應 → 觸發超時機制（見第三節）
```

### 2.2 審查期間的系統預設行為

```
ORANGE審查期間（觸發後至Owner回應前）：

對 P3 BLOCK+CAUTION 情境：
  預設行為：維持 BLOCK（不升至STRONG_BLOCK）
  理由：
    • 失效模式是「過度保守」（升至STRONG_BLOCK後股價上漲）
    • 預設行為應修正失效方向（降低保守程度）
    • 維持BLOCK仍是停止新增投入，不會造成損失

對其他規則：
  預設行為：維持現行規則不變
  理由：ORANGE只影響特定情境，不影響整個系統

加碼比例調整（ORANGE期間自動執行）：
  若 P3 BLOCK+CAUTION 情境觸發：
    原計畫加碼比例 × 0.5（自動降低50%）
  其他情境：不受影響

輸出標籤（每次決策強制附加）：
  ⚠️ [ORANGE審查中] P3 BLOCK+CAUTION規則可靠性下降
  加碼比例已自動降低50%，等待Owner審查確認
  審查期限：{deadline}
```

### 2.3 Owner 審查清單

```
Owner 需要回答的三個問題：

Q1：失效原因判斷
  選項A：規則本身有缺陷（BLOCK+CAUTION不應升至STRONG_BLOCK）
  選項B：市場環境暫時異常（2024Q3/Q4是特殊情況，規則仍正確）
  選項C：數據品質問題（失效案例的判定標準有誤）

Q2：若選A（規則缺陷），修改方向
  選項A1：BLOCK+CAUTION → 維持BLOCK（不升級）
  選項A2：BLOCK+CAUTION → BLOCK（加碼比例降至0%，但不升至STRONG_BLOCK）
  選項A3：其他（Owner自訂）

Q3：修改後的觀察期
  建議：修改後觀察2個季度，確認新規則有效性
  Owner可調整此期限

回應格式（Owner輸入）：
  「ORANGE審查回應：Q1=A，Q2=A1，Q3=2季度」
  或
  「ORANGE審查回應：Q1=B，維持現行規則，下次審查時間=2026-09-30」
```

### 2.4 審查結果的記錄


## 三、超時機制設計

### 3.1 超時定義與觸發

```
超時條件：Owner 超過7個自然日未回應

超時後的系統行為（分階段）：

Day 8~14（超時第1週）：
  • 維持ORANGE預設行為（BLOCK+CAUTION→BLOCK）
  • 每次決策輸出額外警告：
    「⚠️ ORANGE審查已超時{N}天，等待Owner回應」
  • 不自動升級至RED

Day 15~21（超時第2週）：
  • 維持ORANGE預設行為
  • 警告升級：
    「🔴 ORANGE審查嚴重超時{N}天，
      若7天內仍無回應，將自動升級至RED等級」

Day 22+（超時第3週起）：
  • 自動升級至RED等級
  • 觸發RED預設行為（見3.2節）
```

### 3.2 自動升級至 RED 的設計理由

```
為什麼設計超時自動升級？

理由1：Owner長期無回應本身就是一個風險信號
  若Owner超過21天無法審查一個ORANGE問題，
  可能代表：
    a. Owner健康或生活出現問題（需要關注）
    b. Owner認為問題不重要（但系統認為重要）
    c. Owner忘記了（需要提醒機制）

理由2：RED等級的預設行為（HOLD_CAUTION）是安全的
  RED等級不會造成損失，只是更保守
  這是一個「安全失效」（fail-safe）設計

理由3：強制Owner最終必須面對問題
  RED等級的警告更明顯，更難被忽略
  這是一個「升級提醒」機制，而非懲罰

為什麼不立即升級至RED？
  給Owner21天的緩衝，避免因為短暫無法回應
  就觸發最嚴格的保護機制
  21天（3週）是合理的「退休族生活節奏」緩衝
```

### 3.3 RED 等級的預設行為

```
若超時自動升級至RED：

對 P3 BLOCK+CAUTION 情境：
  預設行為：HOLD_CAUTION（不加碼，不減碼）
  理由：RED等級採用最保守的中性預設

對所有其他決策：
  附加標籤：
  「🔴 [RED等級] P3 BLOCK+CAUTION規則已暫停
    系統使用保守預設：HOLD_CAUTION
    請Owner立即審查 EPISTEMIC_REVIEW_SOP.md」

RED等級解除條件：
  Owner回應並完成審查 → 解除RED，回到正常狀態
  Owner確認維持現行規則 → 解除RED，重置失效率計算
  Owner修改規則 → 解除RED，新規則生效
```
